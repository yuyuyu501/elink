# Windows 双机串流测试

日期：2026-09-18。测试对象为本地 Elink 0.4 独立串流核心及新增的显式 `--peer-test` 诊断入口。未使用 Sunshine 或 Moonlight。

SSH 登录成功。通过 SFTP 将测试便携包部署到远端 `C:\Users\10573\ElinkTest-20260918`，传输前后核对 SHA-256：`486f411a0255c17237d96e077e6fb17b2b9958c62f088ec4630a93ac0079c611`。

SSH 进程位于 Session 0，因此用临时交互式计划任务在远端已登录的 Session 16 启动测试；应用以普通用户权限运行。无需远端安装 Python 依赖。两端测试身份和授权独立于正常用户配置。

Tailscale 连续五次探测为直连、10–11 ms。所有成功会话的 ICE 选中候选均为两端 Tailscale 地址上的 UDP，不使用 SSH 隧道传输媒体。SSH 只用于部署、启动和取回报告。

分辨率 1920×1080、目标 60 FPS、H.264/Opus，码率上限默认 20 Mbps。测试记录解码后的画面数量，每秒取样一次；FPS 是各采样窗口平均值，不是游戏渲染 FPS。RTT 来自应用数据通道的 ping/pong，不能等同于操作到画面的端到端延迟。

## 实测结果

| 方向与内容 | 采样时长 | 平均接收 FPS | 通道 RTT 中位数 | 解码情况 |
| --- | --- | --- | --- | --- |
| 远端 → 本机，合成画面 | 25 次一秒采样 | 59.73 | 12.43 ms | D3D11VA，0 错误 |
| 本机 → 远端，合成画面 | 25 次一秒采样 | 59.87 | 11.60 ms | D3D11VA，0 错误 |
| 远端 → 本机，实际桌面 | 30 次一秒采样 | 55.26 | 12.70 ms | 1 次错误，随后回退软件 H.264 |
| 本机 → 远端，实际桌面 | 30 次一秒采样 | 57.56 | 11.90 ms | D3D11VA，0 错误 |
| 远端 → 本机，实际桌面复测 | 90 次一秒采样 | 50.17 | 13.07 ms | D3D11VA，0 错误，但存在卡顿 |
| 远端 → 本机，实际桌面、10 Mbps | 60 次一秒采样 | 54.57 | 13.06 ms | D3D11VA，0 错误，仍有冻结 |

每次采样还包含像素统计、散列等诊断开销，因此总测试时长略大于表中的采样次数。桌面内容和其他负载未严格控制，不能把方向差异全部归因于网络或硬件。

各轮主机均使用 NVENC。实际桌面三轮分别收到 1749/1810/4710 个视频帧和 1591/1601/4643 个音频帧。音频仅接收并解码，没有回放和人工听音验收。

10 Mbps 对照收到 3436 个视频帧、3153 个音频帧；视频 RTP received=65962、lost=141，约 0.21%，低于 20 Mbps 复测的约 1.24%。但最低采样 FPS 仍为 0，通道 RTT 峰值约 489 ms，因此降低码率并未完全解决卡顿。两轮桌面内容和链路时段不同，这不是严格控制变量的带宽实验。

首轮合成串流的媒体指标有效，但等待撤销的诊断步骤超时，整轮 `ok=false`：人工触发撤销晚于 30 秒等待窗口。反向合成测试改为连接后定时撤销，已验证客户端自动断开和两端清理。没有将失败记录覆盖为成功。

## 发现的问题

1. **20 Mbps 下实际桌面存在丢包与卡顿。** 远端到本机首轮视频 RTP 统计 received=63938、lost=726，最低采样 FPS 3.83；90 次采样复测 received=187432、lost=2357，部分窗口 FPS 为 0。复测保持 D3D11VA 且没有解码错误，因此不能把全部卡顿归因于硬件解码。RTP 丢包数字是接收器统计，并非链路抓包。
2. **自动解码模式在一次 FFmpeg 解码异常后永久回退软件，直到重建会话。** 首轮发生一次；加长复测未复现。本轮补充 `last_decode_error` 和逐秒解码器状态记录，便于后续定位；未把未复现的问题宣称已修好。
3. **WASAPI 捕获曾报告 data discontinuity。** 本机向远端发送实际桌面时出现，音频帧仍持续到达；听感、长时间音画同步及不同音频设备仍需专门验收。
4. 本机 TCP 49318 位于 Windows 保留端口范围 49252–49351，测试首次监听被拒绝。改用系统分配的空闲端口后正常；没有修改系统保留范围，也不是认证失败。

## 已覆盖与未覆盖

已验证：真实跨机 TLS 配对、固定主机证书后的认证、WebRTC 视频与音频、Tailscale UDP 直连、键盘按下/释放与手柄状态传输、失焦归零、主机撤销授权后断开、停止后的媒体和输入资源清理。

输入在主机由 `RecordingInput` 记录，不实际注入用户桌面。手柄结果证明协议传输与释放逻辑，不代表实体手柄、游戏内映射或震动验收。未安装 ElinkPad 驱动，未修改驱动签名、Secure Boot 或防火墙。两端防火墙测试前已关闭，本轮不构成防火墙开启时的安装体验验收。

没有执行游戏、没有测输入到显示的端到端延迟、没有验证 GUI 渲染 FPS、120 FPS、DERP 中继、物理断网重连或长时间稳定性。远端已有 ViGEmBus 与 Xbox 蓝牙设备，但本轮不向它们提交测试输入。

## 复现与证据

`Elink.exe --peer-test <config.json>` 或 `python main.py --peer-test <config.json>` 仅在明确传入此参数时执行。普通启动流程不变。配置中的 `root` 必须为新的测试目录；主机仅批准通过临时邀请验证、来源 IP 和名称均匹配的一个测试客户端。退出后撤销测试授权。

主机配置示例：

```json
{"role":"host","root":"C:/ElinkTests/run1-host","bind":"100.98.115.91","port":0,"peer":"100.98.115.92","name":"run1","synthetic":false,"timeout":180}
```

从主机 `ready.json` 通过受信任通道获取端口和临时邀请后，客户端配置示例：

```json
{"role":"client","root":"C:/ElinkTests/run1-client","address":"100.98.115.91:实际端口","invitation":"临时邀请","name":"run1","synthetic":false,"seconds":30,"bitrate":10}
```

诊断的 `ok=true` 表示最低媒体/输入验收通过，不代表 60 FPS 稳定或无丢包；必须结合 samples、stats 和 metrics 判断性能。支持主机 `revoke_after` 定时撤销与客户端 `wait_revoke` 验证断开。

本机详细证据目录：`.artifacts/peer-20260918`，包含各轮结果、日志、RTP/ICE 数据及汇总；测试报告不包含 SSH 密码，密码未写入脚本或配置。回归测试 `python -m pytest -q`：25 项通过，含新增诊断流程的回环配对、媒体、输入释放和撤销清理。

收尾检查：远端临时计划任务 `ElinkPeerTest-20260918` 已移除，远端测试进程和 49318 监听均已退出；本机测试进程均正常退出。独立测试目录及便携程序保留供复查，没有设置开机启动或无人值守服务。

结论：两台电脑已验证可进行双向独立串流；合成画面基本达到 60 FPS，但实际桌面在当前网络上有可见卡顿，尚不符合稳定低延迟游戏串流的验收标准。后续优先排查丢包后的关键帧恢复、发送节奏/码率适应，以及一次异常触发永久软件回退的策略。
