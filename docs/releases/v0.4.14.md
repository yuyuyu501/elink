# Elink 0.4.14 Windows Preview

本版本修复码率被 WebRTC 反馈错误压低、主控端鼠标不可见和网络诊断页重复的问题。

- 编码器默认使用固定优先策略：用户设置的码率会保持为编码目标，不再被接收端 REMB 根据静态画面的瞬时吞吐量直接压到几百 kbps，避免出现 `0.4 Mbps / 5 FPS` 的反馈回路。
- 保留低延迟 CBR/VBV 编码和原有状态栏显示，状态栏继续只显示实际接收码率。
- “使用主控端鼠标”改为主控端软件光标：被控端不合成系统光标，主控端隐藏系统光标并在远程画面上绘制箭头，避免双鼠标和无鼠标。
- 网络诊断从顶层标签页移到设备页的按需弹窗，设备发现与连接仍集中在设备页。

固定优先会优先维持用户设置的编码目标；如果实际链路长期不足，仍可能出现丢包、排队和延迟上升，后续可继续加入基于丢包与 RTT 的应急降码率策略。自动化测试通过不代表双机游戏串流、系统快捷键拦截或不同游戏光标表现稳定，仍需用户安装后手动验收。当前 Windows 预览包未签名。
