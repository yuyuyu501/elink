# 串流分辨率（0.4.21 起）

“控制中心 → 画质与传输设置”现在采用独立的串流分辨率，提供 1280 × 720、1600 × 900、1920 × 1080、2560 × 1440、3840 × 2160。默认 1080p，选择保存在本机设置中，重连和重启后沿用；旧设置没有串流分辨率时使用默认值。

采集仍读取被控电脑的完整桌面。采集后的图像缩放到所选尺寸，转换为 YUV420P 并编码；控制端解码得到同样尺寸的画面，再按窗口大小等比例适配显示。比如被控端是 2560 × 1440，选择 1280 × 720 时，桌面仍为 1440p，传输图像为 720p。低分辨率上采样不会增加真实细节。

目前预设均为 16:9。与被控端桌面宽高比不一致时，编码前会缩放整个桌面到所选尺寸，可能使内容变形；不会裁掉桌面区域。绝对鼠标继续按完整画面的归一化坐标映射，游戏相对鼠标仍转发本机设备位移。后续可增加自定义宽高比和留黑边策略。

目标帧率也只控制串流采集与编码节奏，不改变物理显示器刷新率。超过远端游戏或桌面实际更新速度时不能创造新的画面。当前 H.264 Level 5.2 的宏块速率预算允许预设 4K60、1440p144，1080p 可选到 240 FPS；超出组合会在应用前提示，保留现有连接。是否跑满仍取决于采集、编码、网络、解码和显示性能。

点击“应用并重新连接”后重新协商串流，保留窗口、静音和统计显示偏好。新版本不再调用 Windows 显示设置接口，不修改或恢复被控端的分辨率、刷新率和 DPI，也不再显示缩放倍率选项。

建议两端一起更新。新控制端连接旧被控端时，会发送明确尺寸和 follow_display=False，1080p 及以下仍可用；旧被控端不能接受新增的 1440p / 4K。新被控端不再宣告 display-settings-v1；旧显示接口返回 HTTP 410 和升级提示，不执行 Windows 修改操作。历史版本曾留下的系统设置不会被本次更新猜测或恢复，需要在 Windows 中自行调整。

自动化覆盖完整桌面缩放、真实本机 WebRTC 图像尺寸、画质取消与应用、非法组合保留会话、保存与重载、旧显示接口拒绝。测试不改变机器的系统显示设置。实际游戏帧率和双机体验仍待用户安装后验收。
