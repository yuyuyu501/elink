# 被控端显示设置

0.4.5 起，“控制中心 → 画质与传输设置”中的分辨率指被控电脑正在串流的显示器实际 Windows 分辨率。新增“被控端系统缩放”，改变其桌面文字和控件大小。应用主窗口不再显示画质表单。

每次打开窗口，读取当前会话被控端的显示器、当前分辨率、支持的显示模式、当前缩放和推荐比例。分辨率或缩放不会保存为全局默认值、套用到另一台电脑；帧率、码率、解码器和声音等偏好继续保存。新连接默认跟随被控端当前显示比例。

点击“应用并重新连接”才会修改显示设置。被控端会释放输入，在采集工作线程中释放 DXGI 后修改显示模式，随后重建采集；控制端完成串流重连。正常退出远控时，被控端会尝试恢复进入会话前的分辨率和缩放；应用崩溃、断电或恢复操作被 Windows 拒绝时无法保证恢复。Windows 可能短暂黑屏或重新排列桌面窗口；部分旧应用需要重新打开才能适应缩放。

分辨率通过 EnumDisplaySettingsExW 读取和 ChangeDisplaySettingsExW 测试 / 应用，优先保留原刷新率。缩放通过 DisplayConfig 的相对 DPI 设备请求读取和设置（-3 / -4）；这些 DPI 数据包不是稳定的公开 Windows API。只展示可以读取并识别的档位，接口不可用时禁用缩放并提示原因；不直接修改注册表，不强制注销或安装显示驱动。设置后重新读取实际值，失败时尝试恢复原值，恢复失败会明确报告。

显示修改接口绑定正在使用的会话 ID 和来源地址，使用当前连接固定的 TLS 证书。无会话或其他控制端不能用该接口改变显示。显示操作与会话结束互斥，避免释放采集时同时修改设备。

当前传输最高 1920 × 1080，按实际桌面比例缩小，分辨率必须对齐偶数像素。选择 2560 × 1440 会实际修改被控桌面为该尺寸，但传输最高仍为 1920 × 1080；竖屏和其他比例不会被强行拉伸成 16:9。本版本仍只串流当前主显示器，不增加显示器切换、虚拟屏或 HDR。

旧被控端不提供显示接口时会要求升级，但仍可修改帧率、码率等原有传输设置。请两端升级至 0.4.5。自动化测试使用隔离的显示后端验证权限、修改、失败恢复和重连，不修改 CI 机器的实际显示；真实 Windows 显示能力读取和 EXE 串流自测单独记录。双机实际分辨率 / 缩放变更与不同显卡兼容性仍待用户验收。
