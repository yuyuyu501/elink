# 便携版应用更新

## 用户流程

1. 打开“关于”，点击“检测更新”。默认包括 GitHub 预览版本，可取消勾选。仅查询 `yuyuyu501/elink`，不在启动时自动查询。
2. 新版必须比当前版本高，并包含对应的 `Elink-{version}-windows-x64.zip`。不自动降级，不将同版本的重复发布作为更新。
3. 确认后下载完整便携包。下载期间应用保持可用，可以取消。下载或校验失败不更改当前应用目录。
4. 校验、解压完成后启动独立 Windows PowerShell 助手，正常关闭会话和应用。助手等待原进程退出，交换目录后启动新版；新版进入界面事件循环才确认启动成功。
5. 若文件占用、权限不足或新版无法启动，助手尝试恢复原目录并重新启动旧版。备份和日志保留在相邻 `.Elink-update-*` 目录。若权限或文件占用导致回退也失败，可关闭相关进程，将该目录的 `previous` 手动移回原路径。详情见该目录 `update.log`。

不是安装程序，不写注册表、不提权、不安装驱动，不更新 Tailscale。新版启动后被控服务仍需手动开启。旧配置、设备证书、配对凭据位于独立用户目录，更新不会覆盖它们。备份旧程序不等于备份用户数据；将来若引入不兼容配置迁移，需要先实现数据备份与迁移回退。

## 校验与边界

- 使用 HTTPS 查询最近 100 个 Releases，按版本号排序，可包含 prerelease；忽略草稿和不匹配的资产。读取 GitHub API 的资产 SHA-256，缺失时要求同 Release 的 `SHA256SUMS.txt` 中存在唯一匹配行。
- 每次重定向都限制在 GitHub/API/官方资产域名内。下载校验长度与 SHA-256，限定 1 GiB 下载、3 GiB 展开与 30000 个文件，检查 ZIP 路径、重复名称、符号链接、Windows 保留名称和构建版本。
- 在应用相邻临时目录解压，确保目录交换位于同一磁盘。只操作固定的应用目录、临时 payload 和备份路径。旧应用目录保留，用户放入应用文件夹的额外文件也在旧目录中，不会自动合并进新版。
- 当前 Release 未做代码签名。SHA-256 用于校验下载完整性，信任仍来源于项目 GitHub 发布账户，并非独立签名认证。
- 启动确认只证明界面启动，不代表游戏串流、音视频、硬件编码或手柄兼容性通过验收。新版本仍需正常发布前测试。
- 已有 0.4.0 便携包不包含此功能，首次迁移需手动下载、解压 0.4.1 或更高版本。之后通过应用内更新安装后续 Release。当前默认开发流程已包括打包和发布，用户在安装更新后手动验收。

## 验证

自动测试覆盖版本和渠道选择、取消/确认交互、重定向限制、损坏与截断下载、解压路径攻击、源码替换保护、原目录保护，以及临时目录内真实 PowerShell 替换/回退。光标测试覆盖 Win32 绘制、隐藏状态、热点与边缘裁切、静态桌面重新绘制和缓存不留残影。所有测试使用临时目录，不替换真实安装，也不安装驱动。

2026-09-21 更新功能提交时，本地完整测试 76 项通过；真实 Windows 界面在 900 × 680 与 1120 × 800 检查过“关于”页。源码桌面回环自测收到 91 帧视频、123 帧音频，使用 NVENC / D3D11VA，未发生解码错误；这是功能检查，不是双机游戏性能验收。在线 Releases 查询通过。

从 0.4.1 的打包流程开始，增加真实冻结 EXE 的自动更新检查：在临时目录放置两份本次应用，通过随包助手交换目录、重启并确认配置和旧目录保留。这是同版本的替换机制检查，不能替代将来版本的配置迁移验证，也不能替代用户更新后的手动功能测试。具体结果写入 Release 的 `verification.json`。
